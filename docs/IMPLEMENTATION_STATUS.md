# Modernization implementation status

Updated 28 September 2026. The modernization objective remains in progress.

## Confirmed product direction

- Internal CRM for one organization.
- Google Workspace sign-in; internal accounts are pre-provisioned and matched by verified Google subject.
- One WhatsApp account, with provider integration still pending Meta account/app credentials and number configuration.
- Keep the Vite/React SPA as a single web client and the NestJS API as a modular monolith with PostgreSQL as source of truth.

## Delivered foundation

- Started a Git repository in the application directory and added ignores for secrets, generated files, and dependencies. The adjacent customer/prospect CSVs are outside this repository.
- Added a NestJS 12 API, PostgreSQL migrations, typed database service, OpenAPI docs, health/readiness routes, Helmet, rate limiting, request validation, OIDC JWT verification, local-only development identity, and organization-scoped membership lookup.
- Added lead list/create, E.164 phone normalization, budget validation, role-aware lead visibility, audited lifecycle transitions, explicit self-assignment, assignment history, and capacity checks.
- Expanded persisted leads with organization-scoped search by name/phone/email, stage filters, stable offset pagination with `hasMore`, audited partial edits, audited soft archive that releases active assignments, and an API/UI activity timeline for stage, assignment, and audit events.
- Added immutable qualification form versions with admin/manager draft and publish APIs, typed answer validation, persisted answers/snapshots, score-band classification, lead score updates, audit events, and idempotent submission. Added versioned routing-rule drafts/activation, agent profile controls, dry-run previews, and transactionally locked capacity-aware assign-or-queue execution with persisted explanations/decisions. Qualification and Routing screens now use these APIs when authenticated; route execution is an explicit action rather than an automatic trigger.
- Added WhatsApp Cloud API persistence for conversations/messages, signature-verifiable raw-body webhook handling, provider event deduplication, inbound lead matching, opt-out keyword handling, delivery-state updates, and a database outbox with bounded retry/backoff. The authenticated inbox supports assignment-scoped access, explicit consent recording, mark-read/archive, and queues outbound text only after recorded opt-in and within the 24-hour reply window. Added an API-backed Messages screen and kept provider secrets server-side.
- Replaced the authenticated dashboard's demo fixture metrics with organization- and role-scoped database aggregates for pipeline stage, leads created, qualification/win counts, unread conversations, recent leads, and recent audit activity. Prototype mode still uses the original sample-data screens.
- Added lead CSV import preview/commit for up to 500 rows, row-level validation, normalized phone matching, in-file and active-record duplicate detection, admin/manager controls, import provenance/audit events, transactional rechecks, and skipped-row results. Added role-restricted filtered export with an audit event and CSV formula-injection protection. Migration 008 adds the active organization/phone uniqueness constraint and deliberately stops with a clear error if existing active duplicates need review.
- Replaced authenticated prototype analytics with date-bounded UTC cohort metrics derived from lead records and lifecycle history: creation trend, top sources, current stage distribution, and eventual qualification/win rates. Invalid or overlong date windows are rejected; rates are unavailable when their denominator is zero.
- Configured explicit Express raw-body capture for signed webhooks while raising JSON/urlencoded request limits to 5 MB for reviewed imports; the reverse proxy permits the same bounded request size.
- Added Google Workspace sign-in gate and API-backed Leads, Qualification, Routing, Messages, Dashboard, Pipeline, Analytics, Settings, Team, Help, notification inbox, and global search when API mode is configured. Organization name/default currency are persisted with audit and optimistic version checks; each member's notification preferences are persisted and versioned. Notifications are transactionally produced for lead creation/import, assignment, lifecycle changes, and inbound WhatsApp messages, with user-scoped reads, event preferences, deduplication, and deep links. Admins can provision members by Workspace email, update role/access, and see identity-binding state. OIDC requires a verified email; first login binds a pre-provisioned matching email, and production sign-in fails closed until `OIDC_EMAIL_DOMAIN` is configured. Admins/managers can assign or reassign qualified pipeline leads to active agents; the API checks capacity under the same agent-profile locks used by routing, records the reason/history/audit, and notifies the assignee. The state machine now allows the required qualified-to-assigned transition.
- Added migrations 009–011 for organization defaults and notifications, pre-provisioned team members, and audited WhatsApp conversation assignment history. Migration 010 stops with a clear error if pre-existing duplicate member emails need resolution.

Search result links now preserve lead/conversation selection. Added authenticated CRM Help based on implemented behavior/readiness rather than prototype claims. Apply migration 008 after reviewing its active-phone duplicate preflight on the target database; the import/export workflow and duplicate guard are implemented but DB execution is not yet verified. Run the CI workflow remotely; add database integration/e2e coverage, observability, managed secrets, backup/restore, retention/consent policy, performance and security review, and production operational runbooks once hosting and compliance constraints are known.
